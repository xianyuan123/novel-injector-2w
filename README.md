# Novel Injector（小说注入器）

SillyTavern（酒馆）第三方扩展。先把小说清洗成压缩正文、剧情节点和角色资料，再在聊天时注入相关内容；支持向量检索、穿书进度、用户代入、世界设定与文风。

> **已经支持自定义上下文注入位置。** 打开插件 → **处理** → 向下找到并展开 **注入设置** → 展开要调整的分类，即可设置 **注入位置、注入深度、消息角色**。各类内容可以分别设置，详见下文。

[安装与上手](#安装与上手) · [注入说明](#注入位置与内容) · [穿书与代入](#穿书与用户代入) · [常见问题](#常见问题) · [更新记录](./更新记录.md)

## 安装与上手

在酒馆的扩展安装入口粘贴：

```text
https://github.com/ZZZa-o/novel-injector
```

安装后刷新页面，点击顶部的书本图标打开插件。手动安装则把仓库放到 `SillyTavern/public/scripts/extensions/third-party/novel-injector`，目录内须包含 `manifest.json`、`index.js`、`lib/` 等文件。

1. **处理** → 上传 `.txt` 或 `.mobi` 小说。
2. 点清洗区域的设置齿轮，填写 **清洗 API 地址、Key、模型**。需要兼容 OpenAI Chat Completions 的接口；插件不提供模型。
3. 点 **开始全自动清洗**，等待处理。清洗会产生压缩正文、剧情节点和角色资料，支持暂停与续跑。
4. **阶段** → 开启想让 AI 参考的阶段，再回到聊天窗口发消息。需要调整阶段划分时，到 **剧情** 页操作。

**不做向量化也能使用。** 想按语义检索片段，再到处理页配置兼容 OpenAI Embeddings 的向量接口，选择阶段并向量化。聊天模型与向量模型用途不同，不能混填。

| 页面 | 常用操作 |
|---|---|
| 处理 | 上传、清洗、API 配置、文风生成、向量化、注入设置 |
| 剧情 | 剧情节点编辑、阶段划分、世界设定、偏差分析、穿书模式 |
| 角色 | 角色资料、注入开关、AI 更新人设、用户代入 |
| 阶段 | 阶段开关、标题与概括、角色演绎提示词、未向量注入方式 |
| 设置 | 插件总开关、全局提示词、自动保存、主题、小说库、导入导出 |

## 注入位置与内容

**入口：处理 → 注入设置。** 先展开“注入设置”，再展开其中的“角色人设”“阶段剧情（未向量）”“向量块”等分类。阶段页那一整块注入开关收在顶部的「注入策略」横条里，折叠状态也会记住。

- **注入位置**：`主提示前`、`主提示后`、`聊天内` 三选一。
- **注入深度**：选择“聊天内”时，`0` 表示对话末尾；数字越大，插入位置越靠前。它不是阶段编号，也不是召回数量。
- **消息角色**：`系统`、`用户`、`助手` 三选一，决定这段资料以哪种消息身份发给模型。

**向量块能注入多少？** 展开 **向量块** 后有两个数量控件：

- **单轮最多 Token**：单轮向量片段的总体积上限，默认 `20000`（≈30000 字），范围 256～200000。当前阶段片段优先占用预算，剩下的留给原著前情；装不下的低分片段直接丢掉，不会把正文撑爆。
- **最多召回片段数**：单轮最多取几个片段，默认 `30`（上限 60）。
- **保底召回片段数**：相似度阈值是**及格线**，不是名额。默认 `0`（关闭）时只取及格的片段——及格几个就注入几个，所以你可能会发现「明明把召回数调到 40，却只进来 3～4 块」。把它设成 `40` 就会补齐到 40 块：及格的片段优先，不够再按相似度从高到低把不及格的补进来。范围 0～200。
- **前情最多召回片段数**：原著前情（更早阶段）单独的名额，默认 `2`，范围 0～50。设为 `0` 则不注入前情。
- **向量块切分（字）**：向量化时每个索引块的字符数，默认 `1000`（≈667 Token），范围 200～4000。**改动后需要重新向量化**才会按新粒度建索引，旧块仍按原粒度检索。

> **实际取块数 = max(最多召回片段数, 保底召回片段数)**，再按 Token 预算逐块裁剪。
>
> 一个片段的实际体积 ≈ `向量块切分` × 1.5 Token。默认 1000 字时，单轮 20000 Token 最多只装得下约 30 块——想要 40 块就必须把预算提到 30000 以上（40 × 667 ≈ 26680 Token）。
>
> 常见坑：**预算才是真正的天花板**。哪怕保底设成 200，装不下的块照样在裁剪阶段被丢掉，最后进正文的仍然只有预算允许的那些。

| 分类 | 发给 AI 的内容 | 默认位置 / 深度 |
|---|---|---|
| 全局提示词 | 内置头部、尾部规则 | 头部：主提示前 / 0；尾部：聊天内 / 0 |
| 角色人设 | 已开启的角色资料 | 主提示前 / 4 |
| 阶段剧情（未向量） | 剧情节点或压缩原文 | 聊天内 / 4 |
| 偏差注入 | 已分析出的剧情偏差与分支事实 | 主提示前 / 0 |
| 向量块 | 根据对话检索到的相关片段 | 聊天内 / 4 |
| 世界设定 | 已开启且有内容的世界设定分类 | 主提示前 / 4 |
| 文风 | 已生成的文风执行指南 | 主提示前 / 4 |

以上默认消息角色均为“系统”。全局提示词的来源在 **设置** 页选择：不使用、跟随酒馆预设、使用插件内置。跟随酒馆预设时，可指定插件使用的已保存预设，不影响前台 RP 的预设选择。位置设置只决定资料放在哪里，**不会自动生成资料或打开对应模块**。

### 阶段与向量有什么区别？

**阶段就是一组剧情的开关单位**，例如一卷或一个篇章。普通模式下：

| 阶段状态 | 如何注入 |
|---|---|
| 已开启、已向量化 | 根据当前对话检索相关片段 |
| 已开启、未向量化 | 直接注入该阶段的剧情节点或压缩原文 |
| 已关闭 | 不参与普通模式的阶段注入 |

直接注入的内容在 **阶段 → 未向量注入** 中选择：“剧情节点”更省 Token，“压缩原文”细节更多。

普通模式的直接注入默认上限为 **32000 Token**，可在 **处理 → 注入设置 → 阶段剧情（未向量）** 调整。超出时优先保留当前阶段，再尝试阶段概括，仍放不下的阶段会省略。页面会显示本轮估算用量与省略情况。

**想让 AI 严格按本阶段剧情走？** 打开 **处理 → 注入设置 → 阶段剧情（未向量）** 里的 **当前阶段全量直注**（默认关闭）。开着向量化的玩法也能用：

- **当前阶段**整段剧情（跟随「未向量注入」模式，选节点或压缩原文）直接注入，发的是**这个阶段的全部剧情**，不是当前一个节点；不召回、也不受「单轮最多 Token」裁剪，上限单独放宽到 **200000 Token**；内容真的极长时才会截断。
- **更早的阶段仍然按向量召回**——当前阶段跟剧情，前情靠检索，两者不打架。
- 被整段直注的当前阶段会从召回池里移除，同一段剧情不会注入两次。
- **穿书模式下**：整阶段直注会接管剧情注入，穿书自己那套「当前节点」持续提示词随之暂停，避免同一段节点正文进两次；「开场 / 推进」这类一次性提示词不受影响。
- 开关开着但当前阶段没启用时不生效，面板会提示；没有向量数据时按钮自动隐藏（那种情况本来就会整段直注）。
- 关掉开关，行为与以前完全一致。

**角色、世界设定、文风等有各自的开关或内容条件，不由阶段开关统一控制。** 想停用全部注入，到设置页关闭插件总开关。

### 怕 AI 把剧情走偏？把本阶段剩下的剧情和后面几阶段提前给它看

**入口：处理 → 阶段** 的「**未来剧情预告**」（默认关闭），紧挨着「当前阶段全量直注」。

玩到第 8 阶段第 2 个节点时，当前阶段后面的节点**不该发**——发了就等于剧透，AI 会提前把剧情跳过去。但完全不告诉它「后面大概会发生什么」，它又容易把人物关系、伏笔、关键事件写歪。这个开关就是补这个缺口：

- **当前阶段也算（默认勾选）**：把当前阶段**还没演到**的节点也放进预告——这正是没开「全量直注」时最容易写偏的地方。穿书模式下从「正在进行的那个节点」的**下一个**开始取，已经演过的不会重复发；普通模式没有逐节点进度，就从该阶段第一个节点开始取。
- **往后 N 个阶段**：从当前阶段的**下一个阶段**开始，按顺序取 N 个阶段（默认 1，可填 0～20）。填 0 且勾着「当前阶段也算」= 只预告当前阶段剩下的剧情；填 0 且不勾 = 完全不注入。
- **每阶段 M 个节点**：每个阶段按剧情顺序取前 M 个节点（默认 2，可填 0～20；**填 0 表示这个阶段的全部节点**）。当前阶段同样按这个数量取。
- 注入的内容带一句明确声明：「以下内容尚未演到，只用来把握整体走向、提前埋设伏笔，不要跳过当前剧情直接写，也不要让角色说出此刻还不该知道的细节」。
- 和「未向量注入」共用同一个模式与 Token 上限：选「剧情节点」就发明细节点，选「压缩原文」就发这些阶段涉及的清洗分段（每段截断到 1500 字）。总长超过上限时在**节点边界**处停住，不会把半句话切给模型。
- **不会重复注入**：当前阶段如果已经整段发过了（开了「全量直注」，或它是未向量阶段、走了整阶段注入），预告就自动跳过当前阶段，只发后面的阶段——同一段剧情不会在一轮里出现两次。
- **跳过被关闭、被整段屏蔽的阶段**，也**跳过被屏蔽的节点**——屏蔽规则优先级更高，不会出现「明明屏蔽了却又从预告里冒出来」。
- 面板下方的说明会实时告诉你本轮会注入哪几个阶段；当前是最后一个阶段、或后面没有可用阶段时会提示。
- 「当前阶段」的口径与全量直注完全一致：穿书模式取当前进行节点所在阶段，普通模式取**最后一个开启的阶段**，或者用下面的「进度锚点」手动指定。所以普通模式下想让它从第 8 阶段往后看，可以填个锚点，也可以把 9 之后的阶段先关掉。
- 关掉开关，行为与以前完全一致。

### 阶段页挤成一团？收起来，还能先看一眼这轮到底发什么

**入口：处理 → 阶段** 顶部那条「**注入策略**」横条。未向量注入模式、当前阶段全量直注、全部开启/关闭、未来剧情预告、召回屏蔽都收在这条横条里，默认**折叠**。

- 折叠时横条只留一行摘要，把这轮的注入策略写清楚：召回第几阶段、直注第几阶段、预告从第几阶段到第几阶段、屏蔽了几项。不展开也知道这轮会发什么。
- 点横条展开/收起；键盘聚焦后按**回车或空格**同样可以切换。展开状态会被记住（`stageInjExpanded`）。
- 横条右侧的 **预览** 按钮打开「**本轮注入预览**」：

| 预览分区 | 内容 |
|---|---|
| 向量召回 | 本轮召回的片段（点「预览召回」才会真的去检索，会调用一次向量 API） |
| 当前阶段直注 | 开了全量直注时整段发出去的内容 |
| 未来剧情预告 | 勾了预告时会发出去的后续剧情 |
| 角色人设 / 世界设定 / 文风 / 偏差 / 全局提示词 | 这些设置项各自会注入的正文 |

每段都标了**字符数、Token 估算和占比**，顶部给总账（总字符数、总 Token）。预览用的是**和实际注入同一套构造函数**，所以看到的就是会发出去的，不会「预览一套、实际一套」。除了「预览召回」那一块，其余都是本地计算，不发请求。

### 知道自己在第几阶段，但插件猜错了？用「进度锚点」

**入口：处理 → 阶段** → 展开「注入策略」→ 第一行「**进度锚点**」。

普通模式下插件只能按「最后一个开启的阶段」猜你在哪。如果你开了好几个阶段、实际只演到第 8 阶段，猜出来的位置就可能偏。手动填一下：

- **第 N 阶段**：填了之后，**全量直注取这一阶段**、**未来预告从这一阶段的节点之后开始**。填 `0`（默认）＝按原来的自动口径判断。
- **阶段里的节点**：下拉里按剧情顺序列出该阶段的全部节点，选中的那个会被当作「已经演过」，预告从它**后面**开始。不选就是「从阶段开头」。
- **自动**：清掉锚点，回到自动判断。
- 换阶段会自动清掉节点选择，不会拿上一阶段的节点当锚点；阶段号填越界（比如只有 10 个阶段却填 12）会自动退回自动判断，换小说、重新划分阶段之后也不会锚到一个不存在的阶段。
- **穿书模式本来就有当前节点**，锚点不生效，展开后会直接写明原因。
- 锚点只决定「取哪一阶段」和「预告从哪开始」，**不改全量直注的开关**：那个阶段关着，仍然不会直注。

### 想让某段剧情不要再出现？用「召回屏蔽」

**入口：处理 → 阶段** 每张阶段卡下方的「召回屏蔽」一行。当某个阶段里有一段你不想再让它进上下文的剧情（比如穿越回来后的旧时间线、已经作废的支线），可以直接屏蔽掉。

- **一键屏蔽本阶段**：整个阶段的剧情都不再被召回、也不再被阶段直注。阶段卡会显示「整段已屏蔽」。
- **多选节点**：点开后阶段里的主线 / 支线 / 关键转折会列出勾选框，逐个勾掉不要的节点，再点 **屏蔽勾选**。也可以直接点整行来勾选。
- **一键解除屏蔽**：把该阶段的整段屏蔽与逐个节点屏蔽一起清掉。
- 徽标会实时显示「已屏蔽 3/12」这类进度；被屏蔽的节点在列表里带「已屏蔽」标记。
- **屏蔽按节点本身记住**，不按下标——重新解析、重新划分阶段之后依然有效，刷新页面、重开聊天都在。
- 屏蔽同时管住两条路：向量召回不选它，**阶段直注（含「当前阶段全量直注」与穿书模式的节点注入）也不会发它**。
- 只有当一个原文分段里的节点**全部**被屏蔽（或所在阶段被整段屏蔽）时，这一整块才不召回；同块里还有没被屏蔽的剧情时，该块照常保留，不会误伤。
- **一个要知道的限制**：向量召回的最小单位是「按字数切开的原文片段」（默认 500 字），它和剧情节点不是一一对应的。所以当你只屏蔽了同一原文分段里的**个别节点**、而同块还有别的节点没屏蔽时，这个分段仍可能被召回，被屏蔽节点所在的那几百字也就可能跟着进来。想彻底不让它出现，用 **一键屏蔽本阶段**（整段屏蔽时该分段一定不会进），或者在清洗阶段把这段剧情单独分成一个分段。

#### 玩到第 8 阶段了，前面 1～7 阶段不想要？一键全屏蔽

**入口：处理 → 阶段的列表上方**，「召回屏蔽·全局」工具条。适合「已经推进到很后面的阶段，早期剧情全是已过期的前情」这种局面。

- **一键屏蔽之前阶段**：把**当前阶段之前**的阶段一次性整段屏蔽（例如当前是第 8 阶段 → 屏蔽第 1～7 阶段），**当前阶段与它之后的阶段完全不受影响**。再点一次同一个按钮就是**一键解除**（只解除「之前阶段」的整段屏蔽，不动你手动屏蔽的当前/之后阶段）。
- **当前阶段的判定与注入路径同一套口径**：穿书模式取「当前进行节点」所在阶段；普通模式取最后一个开启的阶段。所以你在第 8 阶段玩，它就会按第 8 阶段算。
- **多选阶段**：点开后每张阶段卡会出现一个勾选框，可**跨阶段勾选**（比如只想屏蔽第 2、5 阶段），勾完点 **屏蔽勾选的阶段（N）** 一次性屏蔽。再点一次「多选阶段」退出。
  - 这个按钮会**跟着勾选内容变意思**：勾的全是已经屏蔽的阶段时，它变成 **解除勾选的阶段屏蔽（N）**（文字会变红边），点一下就把这些阶段解封——所以在多选模式里屏蔽和解除是同一个按钮，不需要记两套操作；勾选里既有已屏蔽又有没屏蔽的阶段时，按「把没屏蔽的补上」处理。
- 工具条右侧会用一句话说明现在算的是第几阶段、之前一共几个阶段、已屏蔽了几个（例如「之前的阶段里已屏蔽 3/7（1、2、5）」）。
- 整段屏蔽某阶段时，顺手清掉该阶段里之前逐个勾选的节点屏蔽——免得以后解除整段屏蔽时冒出早就忘了的节点屏蔽项。
- 同样**不删任何数据**，解除屏蔽立刻恢复原样。

## 清洗与常用参数

清洗统一使用 **设置 → 全局提示词** 中的来源，不再单独选择清洗模式：

| 全局提示词来源 | 清洗请求组成 |
|---|---|
| 内置提示词 | 头部、尾部作为独立消息，按全局位置、深度和角色加入请求；清洗规则、前段参考、本段原文与执行指令分别保留 |
| 跟随酒馆预设 | 读取选定预设的已保存提示词，保留启用条目的角色、顺序和深度，把本次资料与执行指令放入 `chatHistory` 槽位 |
| 不使用 | 只发送清洗规则、资料边界、前段参考、本段原文与执行指令 |

清洗始终使用清洗面板配置的 API 和模型。“插件使用的预设”可选择具体名称，也可保留“跟随前台当前预设”。指定名称后，插件读取该预设的已保存提示词，前台可以使用另一个预设 RP；所选预设被删除时会提示重新选择。新增或更名后，可点击刷新按钮更新列表。

默认位置下，内置全局头部与清洗规则分别作为两条 `system` 消息发送，随后是小说资料和执行指令两条 `user` 消息；预览与实际请求使用同一份消息结构。

预设中的临时历史只用于本次清洗，不写入实际聊天，也不带入前台角色卡、世界书和聊天记录。小说原文不会经过宏展开或身份措辞替换；未启用 `chatHistory` 时，资料追加到预设末尾，预览中会说明。升级保留全局来源和已保存的自定义清洗提示词，移除旧版单独的清洗模式设置。

- **请求结构预览和失败响应记录 / 查看请求**：预览指定分段的消息角色、顺序、全局来源、预设名称和正文。预览不会调用模型；实际发送的请求及失败响应另有记录，仅在当前页面会话保留最近 10 次请求，响应最多展示 24000 字符，不展示接口凭据。
- **续跑清洗**：保留已完成分段，补齐失败和未完成的分段。
- **重新清洗**：先弹出确认框；确认后清空当前清洗结果、剧情、角色、阶段划分和向量索引，从头处理。只是补失败段时，请用“续跑清洗”。
- **生成此段**：只处理选中的一个分段。
- **自动续跑清洗**：默认关闭。开启后会反复补齐未完成分段，直到全部完成；每轮等待 3～30 秒，随时可暂停，全部完成后弹窗提醒。
- 自动清洗中，每段每轮**最多尝试 3 次**。失败提示会显示段号、具体原因和是否还会重试；主动暂停、跳过不会冒充接口故障。
- 同一段的重试复用首次组装的消息与模型配置。单段和自动清洗都优先使用紧邻前段已完成概括的末尾 800 字符作为参考；前段未完成时使用其原文末尾。

| 参数 | 默认值 / 说明 |
|---|---|
| 每段大小 | 100 KB；大段反复超时或截断时可调小，已完成分段会保留 |
| 清洗请求超时 | 15 分钟 |
| 清洗限速 / 并发 | 3 次/分钟 / 1 |
| 向量限速 / 并发 / 每批数量 | 3 次/分钟 / 1 / 16 |
| 基础向量召回 | 参考最近 3 条消息，相似度阈值 0.5，最多召回 30 段（上限 60）+ 前情 2 段（上限 50）；每块 1000 字，单轮总预算 20000 Token（≈30000 字）；保底召回默认关闭 |
| 一键推进（穿书） | 默认关闭；开启后正文状态栏出现「推进」按钮，点击即完成当前节点并跳到下一个未完成节点 |
| 自动保存 | 默认关闭，需要在设置页手动开启 |

## 穿书与用户代入

在 **剧情** 页开启穿书模式，用正文状态栏或弹窗管理进度。

- 按归档进度确定当前节点，完成节点后继续推进；翻看预览不会改变实际注入节点。整阶段完成后不会自动跨阶段，需要手动切换。
- **一键推进**（默认关闭）：在 **剧情** 页的穿书设置里打开后，正文状态栏会出现 **推进** 按钮。点一下 = 把当前节点标记为已完成并前进到下一个**未完成**节点；已经走过的节点会跳过。走到本阶段最后一个节点时按钮会停住，提示该阶段已走完，**不会**自动跨到下一阶段——切阶段仍由你决定（下一阶段解锁后，到阶段列表把当前阶段切到新阶段即可）。
- 穿书模式的直接注入只发送**当前节点**；选择“压缩原文”时发送该节点所在的一个清洗分段。当前节点或正文不可用时会回退到阶段资料。
- 暂停会停用剧情直接注入及开场、推进、持续提示词；向量召回仍可运行，沉浸模式由自己的开关控制。
- 沉浸模式约束角色的信息边界；轻量化召回会裁掉明显晚于当前节点的内容，减少剧透。也可让 AI 推演后文建议。
- **穿书模式会从更早阶段召回前情，包括已关闭的历史阶段。** 关闭历史阶段不等于禁止它作为前情出现。
- 穿书进度按聊天独立保存。

在 **角色 → 用户代入** 中选择原著角色：

| 方式 | 效果 |
|---|---|
| 替换原角人生 | 原角色不再作为独立 NPC 注入，相关称呼按用户身份替换 |
| 扮演原角本人 | 将原角色资料作为用户的既有身份与人物基础 |

代入配置按聊天保存，称呼可以手动增删。替换发生在注入层，不改小说源数据与向量索引。

原著提供参考；如果聊天已改变人物命运或关系，可在剧情页做 **偏差分析**，把已发生的分支事实提供给 AI。偏差分析默认手动触发，也可开启按楼层自动更新。

删除聊天楼层或重新生成（regenerate）、编辑正文、换／删候选回复后，会自动清理来源失效的偏差事实和相关变更记录，同步调整楼层标记并回退受影响的总结进度，无需额外开启。判定靠每层的轻量签名（正文长度＋候选回复条数＋当前选项内容），所以「条数没变、只是原地改写」的重新生成也认得出。缺少来源楼层的旧手填事实会保留。

## 保存与备份

**设置 → 小说库** 可保存、加载、更新和重命名小说快照。长时间处理或编辑前，建议开启自动保存。

| 数据 | 存在哪里 |
|---|---|
| 设置、API 配置、小说库索引 | 酒馆设置 |
| 剧情角色、压缩正文、阶段数据 | 酒馆服务端文件，分别保存为 `*_core.json`、`*_chunks.json`、`*_stages.json` |
| 向量索引 | 当前浏览器的 IndexedDB |
| 穿书进度、用户代入配置 | 当前聊天的数据 |

**跨设备或换浏览器请用“导出 ZIP”备份。** ZIP 包含小说资料、阶段与向量，不包含 API 地址、Key 和模型名。仅复制酒馆设置，不能带走浏览器里的向量。

导入支持 ZIP 和旧版 JSON。导入会新增一本小说快照，**不会立即覆盖当前工作区**；手动加载新快照后才切换。旧版 JSON 不含向量。

## 常见问题

**能不能增加“上下文注入位置”功能？**

已经有。**处理 → 注入设置 → 展开对应分类 → 注入位置 / 注入深度 / 消息角色。** 角色、阶段剧情、向量、世界设定等可以分开调。找不到时，先向下滚动并展开折叠项。

**清洗完了，为什么 AI 还是不知道小说内容？**

先检查插件总开关、阶段开关，以及对应的角色或世界设定是否开启。清洗只是生成资料，聊天时才注入；生成文风、世界设定等也需要操作各自模块。必要时查看酒馆实际发送的提示词，确认资料是否进入上下文。

**不做向量化能用吗？会不会一次把整本书塞进去？**

能用。普通模式只直接注入已开启的未向量阶段，并受 Token 上限约束；穿书模式通常只注入当前节点。想减少消耗，选“剧情节点”并只开启需要的阶段。

**清洗失败，该改哪里？**

| 提示 | 处理方法 |
|---|---|
| 429 / 请求过多 | 降低并发与每分钟请求数，稍后续跑；若提示额度不足，检查余额和配额 |
| 524 / 504 | 网关等待上游超时，稍后重试或减小分段；只提高插件超时通常无效 |
| 401 / 403 / 404 | 分别检查 Key、访问权限、接口地址与模型名 |
| JSON 语法或结构不合规、缺少 ni_meta | 模型没有按要求返回完整结果；重试，反复失败再检查清洗提示词或减小分段 |
| 输出被截断 / 缺少压缩正文 | 减小分段，检查模型输出上限与清洗提示词 |
| 请求超时 / 网络连接失败 | 检查接口、网络与酒馆服务；按需要调整超时或分段大小 |
| 模型拒绝 / 内容过滤 | 在“请求结构预览和失败响应记录”中查看实际返回；核对全局提示词及所选预设是否包含角色扮演、续写等与清洗冲突的要求 |

提示包含实际收到的接口信息。酒馆未提供原始状态码时会明确说明，不会把所有失败都归为同一种原因。只补失败段用 **续跑清洗**，无需整本重洗。

**改了阶段划分，要重新向量化吗？**

受影响阶段的索引会重置，需要重新向量化。更换向量模型后也应重建索引，避免新旧向量不兼容。向量失败可检查地址、Key、模型、限速及批量大小，并使用“诊断”查看缓存。

**AI 更新人设失败，或者某个角色被跳过？**

失败会显示原因，最多额外重试 3 次；截断时可换输出上限更高的模型。如果近期对话没有明确出现该角色姓名或可靠别名，会直接跳过，避免把别人的经历写进此人资料。

**代入角色没有可选称呼？代入会影响向量召回吗？**

称呼来自清洗提取的别名，旧数据可能没有，可手动添加或重洗相关段落。代入不会改向量索引，不影响检索。

**导入会覆盖当前小说吗？分享 ZIP 会带上 Key 吗？**

导入只新增快照，手动加载才切换。导出的 ZIP 不包含 API 地址、Key 和模型名。

**换浏览器后向量没了？**

向量存在浏览器本地。换浏览器或清空站点数据后，需要导入含向量的 ZIP，或重新向量化。

**MOBI 无法上传？**

支持无压缩与 PalmDoc 压缩的 MOBI。DRM 加密、Huff/CDIC 压缩及其他不支持的格式，请先转换为 TXT。

**顶部图标或穿书状态栏不见了？**

顶部图标在酒馆扩展菜单中开启，更新插件后先刷新页面。状态栏则检查剧情页的穿书开关与显示方式；显示异常可先折叠再展开，必要时刷新。

更多改动见 [更新记录](./更新记录.md)。排查日志可在浏览器控制台筛选 `[NI]` 或 `[NI-TB]`；提交问题时请附具体报错文字和操作步骤。
